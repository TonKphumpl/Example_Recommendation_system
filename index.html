1 Introduction to Recommendation Systems

? 1.1 Recommendation System คืออะไร?

Recommendation System (ระบบแนะนำ) คือระบบที่ออกแบบมาเพื่อทำนายความชอบหรือความสนใจของผู้ใช้งาน และแนะนำสินค้า บริการ หรือข้อมูลที่เหมาะสมกับผู้ใช้แต่ละคน

ระบบแนะนำช่วยให้ผู้ใช้สามารถค้นพบสิ่งใหม่ๆ ที่ตรงกับความสนใจได้โดยไม่ต้องค้นหาด้วยตัวเอง ซึ่งมีประโยชน์อย่างมากในยุคที่ข้อมูลมีมากมายเกินกว่าที่มนุษย์จะสามารถประมวลผลได้ทั้งหมด (Information Overload)

ตัวอย่างของระบบแนะนำที่เราพบเห็นในชีวิตประจำวัน:

  • Netflix: แนะนำภาพยนตร์และซีรีส์ที่คุณอาจสนใจ
  • Spotify: สร้าง playlist และแนะนำเพลงที่เหมาะกับรสนิยมของคุณ
  • Amazon: แนะนำสินค้าที่คุณอาจสนใจซื้อ
  • YouTube: แนะนำวิดีโอที่คุณอาจต้องการรับชม
  • Facebook: แนะนำเพื่อนและเนื้อหาที่คุณอาจสนใจ

2 Content-Based Recommendation Systems

📖 2.1 Content-Based Recommendation Systems คืออะไร

Content-Based Recommendation Systems คือระบบที่แนะนำไอเทมให้ผู้ใช้งานโดยอิงจากคุณลักษณะ (features) ของไอเทมนั้นๆ และประวัติความชอบของผู้ใช้ในอดีต

ระบบจะวิเคราะห์ว่าผู้ใช้เคยชอบไอเทมที่มีคุณลักษณะแบบใด และแนะนำไอเทมใหม่ที่มีคุณลักษณะคล้ายคลึงกัน

ตัวอย่างเช่น: หากคุณชอบหนังแนววิทยาศาสตร์ที่มีนักแสดงคนหนึ่ง ระบบจะแนะนำหนังแนววิทยาศาสตร์เรื่องอื่นๆ หรือหนังที่มีนักแสดงคนเดียวกัน

🧠 2.2 เก็บข้อมูลผู้ใช้ (User Profile)

ระบบ Content-Based จะสร้างโปรไฟล์ของผู้ใช้แต่ละคน ซึ่งประกอบด้วยข้อมูลความชอบและพฤติกรรมการใช้งาน โดยจะเก็บรวบรวมข้อมูลเหล่านี้:

  • ไอเทมที่ผู้ใช้เคยให้คะแนนหรือรีวิว
  • ไอเทมที่ผู้ใช้เคยดู เคยซื้อ หรือเคยใช้งาน
  • ความถี่ในการเข้าถึงไอเทมแต่ละประเภท
  • เวลาที่ใช้กับไอเทมแต่ละชิ้น

ข้อมูลเหล่านี้จะถูกนำมาวิเคราะห์เพื่อสร้างโมเดลความชอบของผู้ใช้

🧩 2.3 วิเคราะห์คุณสมบัติของไอเทม (Item Features)

ระบบจะทำการสกัดคุณลักษณะของไอเทมแต่ละชิ้น ตัวอย่างเช่น:

ประเภทไอเทม คุณลักษณะที่วิเคราะห์
ภาพยนตร์ แนวหนัง (genre), ผู้กำกับ, นักแสดง, ปีที่ฉาย, คำบรรยาย, เนื้อหาโดยย่อ
เพลง ศิลปิน, แนวเพลง, จังหวะ (tempo), ความดัง (loudness), ความถี่เสียง
บทความ หัวข้อ, คำสำคัญ, ผู้เขียน, ความยาว, เนื้อหา
สินค้า หมวดหมู่, แบรนด์, ราคา, คุณสมบัติเฉพาะ, คำอธิบายสินค้า

📐 2.4 คำนวณความคล้าย (Similarity)

เมื่อได้คุณลักษณะของไอเทมและโปรไฟล์ผู้ใช้แล้ว ระบบจะคำนวณความคล้ายคลึงระหว่างไอเทมใหม่กับไอเทมที่ผู้ใช้เคยชอบ

2.4.1 TF-IDF (Term Frequency – Inverse Document Frequency)

TF-IDF เป็นเทคนิคที่ใช้ในการประมวลผลภาษาธรรมชาติ (NLP) เพื่อหาน้ำหนักความสำคัญของคำในเอกสาร

TF(t) = (จำนวนครั้งที่คำ t ปรากฏในเอกสาร) / (จำนวนคำทั้งหมดในเอกสาร)
IDF(t) = log(จำนวนเอกสารทั้งหมด / จำนวนเอกสารที่มีคำ t)
TF-IDF(t) = TF(t) × IDF(t)

เทคนิคนี้มักใช้กับระบบแนะนำที่เกี่ยวข้องกับข้อความ เช่น บทความ หรือคำอธิบายสินค้า

2.4.2 Cosine Similarity

Cosine Similarity เป็นวิธีการวัดความคล้ายคลึงระหว่างเวกเตอร์สองตัว โดยวัดจากค่า cosine ของมุมระหว่างเวกเตอร์

Cosine Similarity(A, B) = (A · B) / (||A|| ||B||)
                         = Σ(A₁B₁) / (√Σ(A₁²) √Σ(B₁²))

ค่า Cosine Similarity จะอยู่ระหว่าง -1 ถึง 1 แต่เมื่อใช้กับ TF-IDF (ซึ่งไม่มีค่าลบ) ค่าจะอยู่ระหว่าง 0 ถึง 1

  • ค่าเข้าใกล้ 1 หมายถึงมีความคล้ายกันมาก
  • ค่าเข้าใกล้ 0 หมายถึงมีความคล้ายกันน้อย

2.4.3 สรุป Content-Based Recommendation System

ข้อดี:

  • ไม่จำเป็นต้องมีข้อมูลจากผู้ใช้อื่น (แก้ปัญหา cold-start)
  • สามารถแนะนำไอเทมที่ยังไม่เป็นที่นิยมได้
  • ระบบมีความโปร่งใส - สามารถอธิบายได้ว่าทำไมจึงแนะนำไอเทมนั้น

ข้อจำกัด:

  • Over-specialization - แนะนำแต่ไอเทมที่คล้ายกับสิ่งที่ผู้ใช้เคยดู
  • ต้องมีคุณลักษณะของไอเทมที่ดีพอ
  • ไม่ได้พิจารณาความชอบของผู้ใช้อื่น

3 Collaborative Filtering

👥 3.1 Collaborative Filtering คืออะไร

Collaborative Filtering คือเทคนิคในการแนะนำไอเทมโดยใช้ข้อมูลจากผู้ใช้หลายๆ คน มาร่วมกันสร้างการแนะนำ

หลักการสำคัญคือ: "ผู้ใช้ที่มีความชอบคล้ายกันในอดีต มักจะมีความชอบคล้ายกันในอนาคตด้วย"

แนวคิดนี้คล้ายกับการที่เราขอคำแนะนำจากเพื่อนที่มีรสนิยมคล้ายกับเรา ระบบ Collaborative Filtering มี 2 ประเภทหลัก:

👤 3.2 User-based Collaborative Filtering

ระบบจะมองหาผู้ใช้อื่นที่มีพฤติกรรมหรือความชอบคล้ายกับผู้ใช้เป้าหมาย แล้วแนะนำไอเทมที่ผู้ใช้คล้ายกันชอบ แต่ผู้ใช้เป้าหมายยังไม่เคยใช้

ตัวอย่าง: ระบบแนะนำหนังสือใน Goodreads

สมมติว่าผู้ใช้ A และ B มีความชอบหนังสือคล้ายกัน:

  • ผู้ใช้ A ชอบหนังสือ: Harry Potter, Lord of the Rings, The Hobbit
  • ผู้ใช้ B ชอบหนังสือ: Harry Potter, Lord of the Rings, Game of Thrones

ระบบจะแนะนำ "Game of Thrones" ให้กับผู้ใช้ A และ "The Hobbit" ให้กับผู้ใช้ B

ขั้นตอนการทำงาน:

  1. หาผู้ใช้ที่มีความคล้ายคลึงกับผู้ใช้เป้าหมาย
  2. รวบรวมไอเทมที่ผู้ใช้คล้ายกันชอบ
  3. กรองไอเทมที่ผู้ใช้เป้าหมายเคยใช้แล้วออกไป
  4. จัดอันดับและแนะนำไอเทมที่เหลือ

🔄 3.3 Item-Based Collaborative Filtering

ระบบจะมองหาความสัมพันธ์ระหว่างไอเทมต่างๆ โดยพิจารณาว่าผู้ใช้ที่ชอบไอเทม A มักจะชอบไอเทม B ด้วยหรือไม่

ตัวอย่าง: ระบบแนะนำสินค้าใน Amazon

"ลูกค้าที่ซื้อสินค้านี้มักจะซื้อ..." หรือ "สินค้าที่มักจะถูกซื้อด้วยกัน"

สมมติว่าผู้ซื้อหลายคนที่ซื้อ iPhone มักจะซื้อเคส iPhone และฟิล์มกันรอยด้วย

เมื่อมีลูกค้าใหม่ซื้อ iPhone ระบบจะแนะนำเคส iPhone และฟิล์มกันรอย

ขั้นตอนการทำงาน:

  1. สร้างเมทริกซ์ความสัมพันธ์ระหว่างไอเทม (item-item similarity matrix)
  2. ค้นหาไอเทมที่มีความสัมพันธ์สูงกับไอเทมที่ผู้ใช้เคยชอบ
  3. กรองไอเทมที่ผู้ใช้เคยใช้แล้วออกไป
  4. จัดอันดับและแนะนำไอเทมที่เหลือ

✅ 3.4 สรุป Collaborative Filtering

ข้อดี:

  • ไม่จำเป็นต้องมีข้อมูลคุณลักษณะของไอเทม
  • สามารถแนะนำไอเทมที่แตกต่างจากสิ่งที่ผู้ใช้เคยดู (Serendipity)
  • คุณภาพการแนะนำมักดีขึ้นเมื่อมีข้อมูลผู้ใช้มากขึ้น

ข้อจำกัด:

  • Cold Start Problem - ไม่สามารถแนะนำไอเทมใหม่ที่ยังไม่มีใครใช้
  • Sparsity Problem - ผู้ใช้ส่วนใหญ่มีปฏิสัมพันธ์กับไอเทมจำนวนน้อยเมื่อเทียบกับไอเทมทั้งหมด
  • Scalability - เมื่อจำนวนผู้ใช้และไอเทมเพิ่มขึ้น การคำนวณจะซับซ้อนมากขึ้น

4 Knowledge-Based Filtering

🧪 4.1 Knowledge-Based Filtering คืออะไร

Knowledge-Based Filtering คือระบบแนะนำที่ใช้ความรู้เฉพาะทาง (domain knowledge) และกฎที่ชัดเจนในการแนะนำไอเทม

ระบบนี้ไม่ได้อาศัยข้อมูลจากพฤติกรรมของผู้ใช้ในอดีต แต่ใช้ข้อมูลความต้องการปัจจุบันของผู้ใช้ และความรู้เกี่ยวกับไอเทมและโดเมนโดยตรง

ระบบ Knowledge-Based มักถูกใช้กับสินค้าที่:

  • มีราคาสูง (เช่น บ้าน รถยนต์)
  • ซื้อไม่บ่อย (เช่น คอมพิวเตอร์ โทรทัศน์)
  • มีความซับซ้อนและต้องการข้อมูลเฉพาะทาง (เช่น ประกันภัย เงินลงทุน)

⚙️ 4.2 ตัวอย่างการใช้งาน Knowledge-Based Filtering

ตัวอย่างที่ 1: ระบบแนะนำสินเชื่อบ้าน

ระบบจะถามข้อมูลจากผู้ใช้ เช่น:

  • รายได้ต่อเดือน
  • เงินเก็บ
  • ประวัติการชำระหนี้
  • มูลค่าบ้านที่ต้องการกู้
  • ระยะเวลาที่ต้องการผ่อน

จากนั้นระบบจะใช้กฎและความรู้เฉพาะทางเกี่ยวกับการให้สินเชื่อ เพื่อแนะนำแพ็คเกจสินเชื่อที่เหมาะสมที่สุดสำหรับผู้ใช้

ตัวอย่างที่ 2: ระบบแนะนำสมาร์ทโฟน

ระบบจะถามความต้องการของผู้ใช้ เช่น:

  • งบประมาณ
  • ขนาดหน้าจอที่ต้องการ
  • ความสำคัญของกล้องถ่ายรูป
  • ความต้องการด้านแบตเตอรี่
  • การใช้งานหลัก (เล่นเกม, ถ่ายรูป, ใช้งานทั่วไป)

จากนั้นระบบจะใช้ฐานความรู้เกี่ยวกับสมาร์ทโฟนที่มีในตลาด และกฎการเปรียบเทียบ เพื่อแนะนำโทรศัพท์ที่เหมาะสมที่สุด

✅ 4.3 สรุป Knowledge-Based Filtering

ข้อดี:

  • ไม่มีปัญหา Cold Start - สามารถแนะนำไอเทมใหม่ได้ทันที
  • มีความแม่นยำสูงสำหรับไอเทมที่ต้องการความเชี่ยวชาญเฉพาะทาง
  • ผู้ใช้สามารถควบคุมการแนะนำได้โดยการระบุความต้องการของตนเอง

ข้อจำกัด:

  • ต้องการฐานความรู้ที่มีคุณภาพและครอบคลุม
  • การพัฒนาและบำรุงรักษาฐานความรู้อาจมีต้นทุนสูง
  • ผู้ใช้ต้องให้ข้อมูลความต้องการของตนเอง ซึ่งอาจทำให้เกิดความไม่สะดวก

5 Hybrid Recommender System

🔄 5.1 Hybrid Recommender System คืออะไร

Hybrid Recommender System คือระบบที่ผสมผสานเทคนิคการแนะนำหลายๆ แบบเข้าด้วยกัน เพื่อเพิ่มประสิทธิภาพและลดข้อจำกัดของแต่ละเทคนิค

โดยทั่วไปแล้ว ระบบ Hybrid มักจะผสมผสานระหว่าง Content-Based, Collaborative Filtering และบางครั้งก็รวม Knowledge-Based เข้าไปด้วย

🤝 5.2 แล้วมันผสมกันยังไง?

5.2.1 🎼 Content-based Filtering: รู้ใจเพราะ "คุณชอบอะไร"

ระบบ Content-based Filtering เป็นเหมือนเพื่อนที่รู้จักรสนิยมของเราเป็นอย่างดี

  • ดูว่าเราเคยชอบอะไร
  • วิเคราะห์คุณลักษณะของสิ่งที่เราชอบ
  • แนะนำสิ่งที่มีคุณลักษณะคล้ายกัน

5.2.2 👥 Collaborative Filtering: รู้ใจเพราะ "คนอื่นที่ชอบเหมือนคุณชอบอะไร"

ส่วน Collaborative Filtering เหมือนกับการได้คำแนะนำจากคนที่มีรสนิยมคล้ายกับเรา

  • หาคนที่ชอบสิ่งเดียวกับเรา
  • ดูว่าคนเหล่านั้นชอบอะไรอีก
  • แนะนำสิ่งที่เรายังไม่เคยลอง

5.2.3 🔄 เมื่อสองสิ่งนี้มารวมกัน…

ระบบ Hybrid สามารถผสมผสานทั้งสองแนวคิดได้หลายวิธี:

วิธีการผสมผสานแบบต่างๆ

  • Weighted Hybridization: ให้น้ำหนักผลลัพธ์จากแต่ละระบบ แล้วรวมคะแนนเข้าด้วยกัน
  • Switching Hybridization: เลือกใช้ระบบที่เหมาะสมที่สุดในแต่ละสถานการณ์
  • Cascade Hybridization: ใช้ระบบหนึ่งเพื่อกรองผลลัพธ์เบื้องต้น แล้วใช้อีกระบบเพื่อจัดอันดับผลลัพธ์ที่เหลือ
  • Feature Combination: นำคุณลักษณะจากระบบหนึ่งไปใช้ในอีกระบบหนึ่ง

ตัวอย่างเช่น: Netflix ใช้ทั้ง Content-based (แนวหนัง, นักแสดง) และ Collaborative Filtering (พฤติกรรมการรับชมของผู้ใช้คนอื่น) ร่วมกันในการแนะนำภาพยนตร์และซีรีส์

5.2.4 สรุปสั้นๆ Hybrid Recommender System

ข้อดี:

  • แก้ไขจุดอ่อนของแต่ละระบบ เช่น ปัญหา Cold Start ในระบบ Collaborative
  • เพิ่มความแม่นยำในการแนะนำ
  • สามารถปรับให้เหมาะกับสถานการณ์ต่างๆ ได้

ข้อจำกัด:

  • มีความซับซ้อนในการพัฒนาและดูแลรักษา
  • อาจต้องการทรัพยากรการประมวลผลมากกว่า
  • ต้องการข้อมูลมากกว่าระบบแบบเดี่ยว

# Import libraries
import numpy as np
import pandas as pd
from sklearn.metrics.pairwise import cosine_similarity

# สร้างตัวอย่างข้อมูลการให้คะแนนหนังของผู้ใช้
# แถว = ผู้ใช้, คอลัมน์ = หนัง
ratings = pd.DataFrame({
    'Movie A': [5, 4, 0, 0, 1],
    'Movie B': [4, 5, 0, 0, 0],
    'Movie C': [0, 0, 5, 4, 0],
    'Movie D': [0, 0, 4, 5, 0],
    'Movie E': [1, 0, 0, 0, 5]
}, index=['User 1', 'User 2', 'User 3', 'User 4', 'User 5'])

print("ตารางคะแนนหนังของผู้ใช้:")
print(ratings)

# คำนวณความคล้ายระหว่างผู้ใช้ด้วย Cosine Similarity
user_similarity = cosine_similarity(ratings)
user_similarity = pd.DataFrame(user_similarity, 
                              index=ratings.index, 
                              columns=ratings.index)

print("\nความคล้ายระหว่างผู้ใช้:")
print(user_similarity)

# ฟังก์ชันสำหรับแนะนำหนังให้ผู้ใช้
def recommend_movies(user_id, num_recommendations=2):
    # หาผู้ใช้ที่คล้ายกับ user_id
    similar_users = user_similarity.loc[user_id].sort_values(ascending=False)[1:]
    
    # หนังที่ user_id ยังไม่เคยดู
    unwatched_movies = ratings.loc[user_id][ratings.loc[user_id] == 0].index
    
    recommendations = {}
    
    # คำนวณคะแนนแนะนำสำหรับแต่ละหนังที่ยังไม่เคยดู
    for movie in unwatched_movies:
        movie_ratings = ratings[movie]
        weighted_sum = 0
        similarity_sum = 0
        
        for similar_user, similarity in similar_users.items():
            # ถ้าผู้ใช้ที่คล้ายกันให้คะแนนหนังนี้
            if movie_ratings[similar_user] > 0:
                weighted_sum += similarity * movie_ratings[similar_user]
                similarity_sum += similarity
        
        # คำนวณคะแนนแนะนำ
        if similarity_sum > 0:
            recommendations[movie] = weighted_sum / similarity_sum
    
    # เรียงลำดับหนังตามคะแนนแนะนำ
    sorted_recommendations = sorted(recommendations.items(), 
                                   key=lambda x: x[1], 
                                   reverse=True)
    
    return sorted_recommendations[:num_recommendations]

# ทดลองแนะนำหนังให้ผู้ใช้แต่ละคน
for user in ratings.index:
    print(f"\nหนังที่แนะนำสำหรับ {user}:")
    recommendations = recommend_movies(user)
    for movie, score in recommendations:
        print(f"- {movie}: คะแนนแนะนำ = {score:.2f}")

🏢 6.2 Example Recommendation system in business

กรณีศึกษา: ระบบแนะนำสินค้าของ Amazon

Amazon เป็นหนึ่งในบริษัทที่ประสบความสำเร็จอย่างมากในการใช้ระบบแนะนำ โดยใช้เทคนิค Item-Based Collaborative Filtering เป็นหลัก

ข้อมูลน่าสนใจ: มีการประมาณการว่า 35% ของยอดขายของ Amazon มาจากระบบแนะนำสินค้า

กลยุทธ์หลักในระบบแนะนำของ Amazon:

  1. ความเฉพาะตัว (Personalization)

    Amazon ปรับแต่งหน้าเว็บไซต์สำหรับผู้ใช้แต่ละคน ทั้งหน้าแรก, หน้าสินค้า, และอีเมลการตลาด

  2. การแนะนำหลายรูปแบบ
    • "ลูกค้าที่ซื้อสินค้านี้มักจะซื้อ..." - Item-Based Collaborative Filtering
    • "คุณอาจจะสนใจสินค้าเหล่านี้..." - Personalized Recommendations
    • "สินค้าที่เกี่ยวข้องกับสิ่งที่คุณดู" - Content-Based Filtering
    • "รายการยอดนิยม" - Popularity-Based Recommendations
  3. การเก็บข้อมูลหลายมิติ

    Amazon ไม่ได้ดูแค่ประวัติการซื้อ แต่ยังเก็บข้อมูลการเยี่ยมชมหน้าเว็บ, การค้นหา, การให้คะแนนสินค้า, รีวิว, และการเพิ่มสินค้าลงตะกร้า

  4. ระบบ Real-time

    ระบบแนะนำของ Amazon ทำงานแบบ real-time ซึ่งหมายความว่าการแนะนำจะเปลี่ยนแปลงทันทีที่ผู้ใช้มีปฏิสัมพันธ์กับหน้าเว็บ

  5. การทดสอบ A/B อย่างต่อเนื่อง

    Amazon ทำการทดสอบอย่างต่อเนื่องเพื่อปรับปรุงอัลกอริทึมและการแสดงผลการแนะนำ

สถาปัตยกรรมระบบแนะนำของ Amazon (โดยคร่าว):

1. การเก็บข้อมูล (Data Collection)

  • เก็บข้อมูลการใช้งานจากช่องทางต่างๆ (เว็บไซต์, แอพ, อุปกรณ์ Echo)
  • บันทึกพฤติกรรมผู้ใช้: การคลิก, การซื้อ, การให้คะแนน, การค้นหา, เวลาที่ใช้บนหน้าสินค้า

2. การประมวลผลข้อมูล (Data Processing)

  • ใช้ Apache Spark และ AWS EMR สำหรับการประมวลผลข้อมูลขนาดใหญ่
  • วิเคราะห์ความสัมพันธ์ระหว่างสินค้า (Item-Item Correlation)
  • สร้างโมเดลความชอบของผู้ใช้

3. การสร้างการแนะนำ (Recommendation Generation)

  • ใช้เทคนิคผสมผสานระหว่าง Collaborative, Content-Based และ Knowledge-Based
  • คำนวณ similarity scores ระหว่างสินค้าและระหว่างผู้ใช้
  • จัดอันดับสินค้าตามความน่าจะสนใจสำหรับผู้ใช้แต่ละคน

4. การนำเสนอ (Presentation)

  • แสดงการแนะนำในตำแหน่งต่างๆ บนเว็บไซต์และแอพ
  • ปรับแต่งการนำเสนอตามผลการทดสอบ A/B
  • ส่งการแนะนำผ่านช่องทางอื่นๆ เช่น อีเมล, การแจ้งเตือนบนแอพ

ผลลัพธ์ทางธุรกิจ:

  • เพิ่มยอดขายระหว่าง 35-45%
  • เพิ่มความผูกพันของลูกค้า (Customer Engagement)
  • เพิ่มมูลค่าตลอดชีวิตของลูกค้า (Customer Lifetime Value)
  • เพิ่มอัตราการแปลงเป็นลูกค้า (Conversion Rate)
